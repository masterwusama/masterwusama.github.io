# 《RMMV 式网页生存 RPG》设计文档

> 项目代号：`rpg`（站点根目录 `rpg/`，导航新增"在线游戏"入口）
> 参考对象：《恐惧与饥饿》（Fear & Hunger，RPG Maker MV 制作）
> 状态：设计定稿，待 M0 启动

---

## 1. 项目定位

### 1.1 目标
纯前端、零依赖、零构建的 2D 俯视角恐怖生存 RPG，直接在 GitHub Pages 上运行，实现类似《恐惧与饥饿》（RMMV 式）的完整玩法闭环：

- 地图探索（tile 地图、碰撞、摄像机跟随、区域触发器）
- 事件与对话（节点化剧本、flag 状态驱动）
- 回合制战斗（指令菜单、状态效果、胜负分支）
- 生存压力（饥饿 / 精神 / 体力 / 时间系统）
- 多槽位存档（存档点制）

### 1.2 非目标
- 不做实时动作战斗（保持回合制）
- 不做 3D、不做光影引擎
- 不做联机 / 云存档
- 不做构建工具链（保持"打开即玩"）

### 1.3 技术约束
| 项 | 约束 |
|---|---|
| 语言 | 原生 JavaScript（ES5/ES6 兼容，与现有 dnd-table 一致） |
| 渲染 | Canvas 2D（单 Canvas，分层绘制） |
| 依赖 | 零外部库；素材为本地文件 |
| 存档 | localStorage |
| 部署 | GitHub Pages 静态目录，无服务器 |

## 2. 核心设计原则（承接文字冒险的教训）

上一版文字冒险失败根因：**剧本撰写过于自由**——文本段格式随意、goto 任意跳转、剧情状态隐式散落，导致线路顺序错乱且无法校验。本项目的剧本设计必须杜绝该问题：

1. **数据与引擎严格分离**：剧本/地图全部为纯数据文件，引擎只解释数据，不写死剧情。
2. **节点类型化**：所有剧情节点必须有明确 `type`（dialog/check/battle/effect/cutscene），禁止自由文本结构。
3. **剧情顺序由"地图可达性 + flag 前置条件"双重控制**：节点只有满足 `cond` 才可触发/可见；玩家必须"走到某个地方、拿到某个东西"才能推进，而非自由跳转。
4. **所有剧情状态显式化**：一律使用命名 flag（`区域_事件`），引擎不隐式记忆任何状态。
5. **校验工具是开发流程的一部分**：剧本每次修改必须过校验器（不可达节点 / 孤儿 flag / 悬空引用 / 死锁），与旧 verify_all.js 同思路，但按新 schema 重写。

## 3. 系统架构

### 3.1 模块划分

```
index.html（单入口）
└─ src/ 引擎层（全部为 ES5 风格 IIFE，挂载到全局 Game 命名空间）
   ├─ core.js        主循环（requestAnimationFrame + 固定时间步）、场景管理、时间系统
   ├─ input.js       键盘输入（方向/WASD、Z=确认、X=取消/菜单、Esc=菜单）
   ├─ map.js         tilemap 加载、碰撞检测、区域触发器、地图切换
   ├─ renderer.js    Canvas 分层渲染（地面层 → 实体层 → 遮罩层 → UI 层）
   ├─ camera.js      摄像机跟随 + 平滑插值 + 边界钳制
   ├─ player.js      玩家实体（移动、状态、面向）
   ├─ npc.js         NPC 实体（站立/巡逻/对话触发）
   ├─ event.js       事件系统：触发器 → 剧本节点解释执行（核心状态机）
   ├─ dialog.js      对话窗口（打字机、选项、检定展示）
   ├─ battle.js      回合制战斗场景（独立子状态机）
   ├─ status.js      生存状态（饥饿/精神/体力/流血/断肢/时间）
   ├─ inventory.js   背包、物品使用、装备
   ├─ save.js        多槽位存档（localStorage）
   ├─ ui.js          RMMV 风窗口组件库（CSS + DOM 实现）
   └─ data.js        数据注册表（地图/剧本/敌人/物品的加载与合并）
```

### 3.2 运行时状态机

```
TITLE（标题画面）
  └→ EXPLORE（地图探索）←────────────┐
       ├→ DIALOG（对话/事件）          │
       ├→ BATTLE（战斗）               │
       ├→ MENU（菜单：物品/状态/存档） │
       └→ SAVEPOINT（存档点）          │
       └→ GAMEOVER / ENDING → TITLE ──┘
```

- 主循环持有当前场景对象（`scene.enter/update/render/exit`）
- 对话/战斗/菜单都是"推入式"子场景：暂停 EXPLORE 更新，返回时恢复

### 3.3 主循环
- `requestAnimationFrame` 驱动；逻辑用固定时间步（50ms），渲染插值
- 每帧流程：input → update(逻辑) → render(分层绘制)

## 4. 地图系统

### 4.1 数据格式（map JSON，存于 `data/maps/`）

```json
{
  "id": "cellar",
  "name": "地窖",
  "tileSize": 32,
  "width": 40,
  "height": 30,
  "tileset": "assets/tilesets/cellar.png",
  "layers": {
    "ground": [ [0, 0, 1, 1, ...], ... ],
    "obj":    [ [-1, -1, 5, 6, ...], ... ]
  },
  "collision": [ [0, 0, 1, 1, ...], ... ],
  "npcSpawns": [
    { "id": "oldman", "x": 12, "y": 8, "dir": "down", "trigger": "n_oldman" }
  ],
  "triggers": [
    { "x": 5, "y": 4, "w": 2, "h": 1, "type": "enter", "node": "cellar_locked_door", "once": true, "cond": { "flag": "cellar_door_open", "op": "==", "val": false } }
  ],
  "exits": [
    { "x": 0, "y": 10, "to": "town", "toX": 38, "toY": 10 }
  ],
  "autostart": null
}
```

### 4.2 碰撞
- 移动目标 tile 的 `collision` 值：0 可走 / 1 阻挡 / 2 水域（减速）
- 实体边界按 0.5 tile 内缩，贴墙时按轴分离滑动
- 半遮挡物件（屋檐、大树）：`obj` 层 tile 可带"遮盖"属性，玩家被遮时该 tile 绘制 alpha 0.5

### 4.3 摄像机
- 跟随玩家，lerp 平滑；钳制在地图边界内；可选缩放（1x，不做缩放以避免像素糊）

### 4.4 触发器类型
| type | 触发时机 | 说明 |
|---|---|---|
| `enter` | 玩家进入矩形区域 | 常用 `once` + `cond`（条件不满足则不触发，之后满足可再次进入触发） |
| `interact` | 玩家面向 NPC/标记点按 Z | NPC 交互、调查点 |
| `step` | 踩到特定 tile | 陷阱、剧情地板 |
| `autostart` | 进入地图立即 | 过场演出 |

## 5. 剧本 / 事件系统（核心设计）

### 5.1 节点 schema（统一格式，引擎唯一解释入口）

```json
{
  "id": "cellar_locked_door",
  "type": "dialog",
  "cond": { "flag": "cellar_door_open", "op": "==", "val": false },
  "text": ["门锁得死死的。", "钥匙孔里结着蛛网。"],
  "choices": [
    { "text": "用钥匙开门", "goto": "cellar_door_unlock", "need": { "flag": "has_cellar_key", "op": "==", "val": true }, "effect": { "flag": "cellar_door_open", "val": true } },
    { "text": "再试试", "goto": "cellar_locked_door_again" },
    { "text": "离开", "goto": null }
  ],
  "once": true
}
```

字段约定：
- `id`：全剧本唯一
- `cond`：可选，进入条件（不满足则引擎拒绝触发；enter 触发器 + cond 组合实现"事件门"）
- `text`：文本行数组（逐行显示）
- `choices[].need`：可选，该选项可见/可选的前置条件
- `choices[].goto`：指向下一节点 id；`null` 表示结束对话（返回地图）
- `choices[].effect`：可选，选择时立即执行的状态写入
- `once`：对话结束后该节点置为已消费（本地记录）

### 5.2 节点类型

| type | 行为 |
|---|---|
| `dialog` | 文本 + 选项；选项可带 need/effect/goto/check |
| `check` | 检定（属性或技能，d20 + 修正 vs DC），成功/失败分支 `win`/`fail` |
| `battle` | 进入战斗；`win`/`lose` 分支（lose 走特殊剧情而非直接死亡，见 §7.4） |
| `effect` | 纯状态写入（加物品/改 flag/扣血/推进时间），可带 `goto` 链 |
| `cutscene` | 演出脚本：NPC 移动 → 文本 → 屏幕效果 → 继续（简单命令序列） |

### 5.3 flag 系统（唯一的状态真相）

- 命名规范：`<区域>_<事件/状态>`（如 `cellar_door_open`、`town_well_pulled`）
- 值类型：bool / number（计数器、好感度）
- 初始白名单：`data/flags.js` 声明所有初始 flag（校验器强制）
- **只读约束**：cond/need 引用的 flag 必须存在写入点或初始白名单；写入的 flag 必须被声明——杜绝隐式状态

### 5.4 剧本校验器（`tools/verify.js`，本地运行，不入库）

延续旧 verify_all.js 的思路，按新 schema 重写：

1. **引用完整性**：goto / 触发器 node / npc trigger 目标必须存在
2. **类型合法**：type / op 枚举合法；cond/need/effect 结构合法
3. **flag 审计**：读到的 flag 均有写入点或初始值；写入的 flag 均有声明
4. **可达性**：从每张地图的入口（autostart/exits 反向）做图遍历，列出不可达节点
5. **死锁检测**：存在 options 节点且所有选项 need 不可同时满足 → 报错
6. **once 滥用**：once 节点若含非 once 前置 → 提示
7. **地图校验**：tilemap 宽高一致、collision 层齐全、exit 目标存在、触发器矩形在地图内

> 校验器是开发流程门禁：**剧本数据不通过校验禁止合入**。

### 5.5 剧情顺序的保证（对比旧方案）

| 维度 | 旧文字冒险 | 新设计 |
|---|---|---|
| 文本格式 | 自由文本段（`说话者— 内容`、`[技能名] 内容`） | 结构化节点，无自由格式 |
| 跳转 | 任意 goto，无约束 | goto 必须指向存在节点；节点可用 cond 封锁 |
| 剧情状态 | 隐式散落 | 全量显式 flag + 校验审计 |
| 顺序控制 | 靠作者自觉 | 地图可达性（走得过去）+ flag 条件（拿得到钥匙）双重强制 |
| 验证 | 事后人工排查 | 校验器门禁 |

## 6. 战斗系统（RMMV 式回合制）

### 6.1 触发方式
- 明雷：地图上可见敌人实体，接触触发 `battle` 节点
- 暗雷：`step` 触发器 + 概率（示例先不做，保留接口）

### 6.2 回合流程
1. 敌我按速度（AGI + 修正 + 随机）排序行动
2. 我方指令菜单：**攻击 / 技能 / 道具 / 防御 / 逃跑**
3. 结算：命中（攻击力 vs 防御力区间随机）→ 伤害 → 状态效果
4. 胜利：经验/物品 → 返回 `win` 分支节点
5. 逃跑：成功率 = 速度差，失败则敌方先手

### 6.3 状态效果（战斗内与战斗外持续）
| 效果 | 表现 |
|---|---|
| 流血 | 每回合/每步扣 HP |
| 中毒 | 每回合扣 HP（弱于流血但持久） |
| 恐惧 | 攻击力减半，小概率跳过行动 |
| 断臂 | 无法攻击/使用双手技能 |
| 断腿 | 速度减半（战斗与移动均生效） |
| 黑暗 | 精神持续下降（区域属性） |

### 6.4 失败惩罚（恐惧与饥饿式）
- 战斗失败**不直接 Game Over**：进入"濒死"剧情——醒来时身处其他地点、失去部分道具、状态恶化，主线继续推进但代价沉重
- 真正 Game Over 只保留"全灭级"特殊事件，且提供"接续时刻"选项（读最近存档点/转生）

### 6.5 数据格式
```json
{
  "id": "rat_king",
  "name": "鼠王",
  "sprite": "assets/enemies/rat_king.png",
  "hp": 46, "atk": 8, "def": 4, "agi": 6,
  "gold": 12,
  "skills": [ { "id": "bite", "rate": 0.6 }, { "id": "dirty_strike", "rate": 0.2 } ],
  "loot": [ { "item": "rat_meat", "rate": 0.7 } ]
}
```

## 7. 生存状态系统

### 7.1 核心数值
| 数值 | 行为 |
|---|---|
| HP | 归零进入濒死剧情 |
| SP | 技能消耗；休息/道具回复 |
| 饥饿 | 随步数/时间衰减；≥80 每 30s 扣 1 HP；进食回复；饥饿归零持续扣血 |
| 精神 | 黑暗/恐怖事件/见血下降；休息/酒类回复；低精神触发幻觉（画面噪点+幻觉对话） |
| 体力 | 奔跑消耗；体力过低攻击力下降、不可奔跑 |
| 金钱 | 商店/赎金（后续扩展） |

### 7.2 时间系统
- 游戏内时钟：每 4 现实秒推进 1 游戏小时（可调）
- 昼夜影响：夜晚敌人强度 +、精神衰减 +、部分区域/人物仅在特定时段开放
- 剧情节点可依赖时段（cond 支持 `time` 条件）

### 7.3 休息与存档点
- 篝火/床：恢复 HP/SP，推进到次日上午（触发夜间事件结算）
- 存档点：同一地点提供存档选项（**不自由存档**，维持压迫感）

## 8. UI 设计（RMMV 风）

### 8.1 视觉基调
- 窗口：白边框 + 深色底 + 投影（CSS 实现，参考 RMMV 默认 Window 样式）
- 主色调：暗褐/墨绿/血红色点缀；标题字体衬线体

### 8.2 布局
| 区域 | 内容 |
|---|---|
| 左上 HUD | HP / SP / 饥饿 / 精神 条形 + 图标 |
| 右上 HUD | 金币、游戏时钟（时段图标） |
| 底部 | 对话窗口（打字机，Z 继续）；选项列表（上下选择 + Z 确认） |
| Esc 菜单 | 物品 / 状态 / 装备 / 存档（RMMV 纵向列表） |
| 战斗 | 上方敌方立绘+名称，下方我方状态行，右侧指令菜单 |

### 8.3 特效
- 对话打字机、选项高亮框、伤害数字飘字、战斗屏幕震动（浅）
- 幻觉状态：Canvas 噪点滤镜 + 对话文本掺入幻觉行

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 美术素材瓶颈（氛围感最大来源） | 占位图先行，P1 起分批替换；素材规格兼容 RMMV 免费资源池 |
| 剧本约束过死 → 表现力受限 | 类型化 + cond/need 已覆盖绝大多数叙事结构；确需新形态时**扩展节点类型**而非放开自由文本 |
| 引擎规模失控 | 严格按模块划分，单模块 <500 行；校验器 + 浏览器回归 |
| 平衡性 | 数值全部集中在 data 文件，便于调参；战斗公式简单（区间随机） |
| 存档兼容 | 存档带版本号 + 迁移函数 |

| 项 | 决策 |

| 题材 | 原创恐怖小镇（失踪案 + 邪教氛围，贴近恐惧与饥饿） |
