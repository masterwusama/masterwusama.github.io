# 模拟持仓模块设计文档

> 路径：`/stock-data/portfolio/`（博客导航「价值分析 → 模拟持仓」）
> 引擎：`stock-data/scripts/portfolio_engine.py`（零依赖，仅标准库）
> 数据：`stock-data/portfolio/data/`（引擎产出，Actions 自动提交）

## 1. 模块定位

对价值分析站跟踪的 A 股标的，用三种经典价值投资策略各管理一个 20 万初始资金的
虚拟组合。每个交易日收盘后自动运行一次：按当日收盘价与最新评分执行分红入账、
分批买卖，并记录净值与全部调仓流水。目的是把站内评分体系（四大流派分、价格参考
系、管理/造假分）落到一套可长期验证的机械化策略上，观察各流派的实际表现。

不做的事：不接真实交易、不计手续费与印花税、不算红利税（见 §8）。

## 2. 三大策略

### 2.1 质量门槛（买入候选的前置过滤）

| 层级 | 条件 | 说明 |
|---|---|---|
| 全局硬门槛 | 造假分 < 30 且 管理分 > 55 | 三策略共用，任何买入都要过 |
| 施洛斯烟蒂 | 无额外要求 | 流派风格即"分散捡便宜"，不设质量档 |
| 格雷厄姆防御 | 格雷厄姆防御分 ≥ 75 且 管理分 ≥ 70 | 防御型投资者要求稳健经营记录 |
| 巴菲特芒格 | 巴菲特分 ≥ 70 且 管理分 ≥ 80 | 只买伟大公司，宁缺毋滥 |

此外必须命中买点：现价 ≤ 该流派买入参考价（`scores.priceRefs[school].buy`）。
买点本身由评分体系的二分法反推得出（施洛斯=净资产锚、格雷厄姆=PPA 公式值、
巴菲特=持久盈利能力资本化值），详见《stock-data 价格参考算法》相关记录。

### 2.2 买入档位（折价深度驱动，不到档位不执行）

每档买入金额 = 初始资金 × 单票上限 ÷ 3。现价相对买点的折价深度决定应持档位：

| 策略 | 第 1 档（1/3 上限） | 第 2 档（2/3 上限） | 第 3 档（满上限） | 单票上限 |
|---|---|---|---|---|
| 施洛斯烟蒂 | 折价 ≥ 3% | ≥ 8% | ≥ 15% | 8% |
| 格雷厄姆防御 | ≥ 5% | ≥ 10% | ≥ 15% | 6% |
| 巴菲特芒格 | ≥ 2% | ≥ 5% | ≥ 10% | 15% |

- 初始化时折价已深则直接买到对应档位（如折价 20% 即一次买满 3 档）。
- 档位设计贴合流派：巴菲特标的极少深折价，故档位浅、建仓快但单票上限高；
  格雷厄姆防御稳步三档摊低成本；施洛斯买点极保守，3% 起接、越跌越买。
- **不设持股数量上限**：分散度由现金池与单票上限自然约束，资金量变大后
  能容纳更多标的。
- 整手约束：A 股按 100 股整手买入；若单档金额不足一手（高价股，如每档
  1 万对 119 元的汾酒），以一手为一档保证能建仓（实际权重可小幅超出名义上限）。

### 2.3 卖出档位（各策略独立三档价位表，触及一档卖一档）

每档卖出当前持仓的 1/3（末档清仓），价位表按流派哲学差异化：

| 策略 | 第 1 档 | 第 2 档 | 第 3 档（清仓） | 理念 |
|---|---|---|---|---|
| 施洛斯烟蒂 | ≥ 保守卖出价 | ≥ 公允价 | ≥ 公允价×105% | 低估修复即兑现，腾钱换下一根烟蒂 |
| 格雷厄姆防御 | ≥ 保守卖出价 | ≥ 公允价 | ≥ 公允价×110% | 纪律止盈，不赚最后一个铜板 |
| 巴菲特芒格 | 保守价**不卖** | ≥ 公允价 | ≥ 公允价×125% / ×150% | 好公司保守价仍便宜，让利润奔跑 |

- 按**最高触发档位**减档：某档参考价缺失（null）时，高档触发仍正确减到高档位。
- 减仓后价格回落到买入档位区间时，加仓机制会重新买回（网格式低接高抛）。

## 3. 每日调仓流程

```
读取最新数据（fetch_data.py 刚更新的 data/）
  └─ 交易日 = 各 company JSON 的 snapshot.time 日期（非抓取时刻，周末兜底）
  └─ 该交易日已入账 → 幂等跳过（周末/节假日/重跑安全）
对每个策略：
  0. 分红除权入账（见 §4，先于买卖，档位判定基于除权后持股）
  1. 卖出检查：现价触及卖出档 → 逐档减仓（清仓则移出持仓）
  2. 持仓加仓：折价加深到更高买入档 → 按折价深度优先补买
  3. 新建仓：未持有的候选命中买入档 → 按折价深度降序依次买入
  4. 按收盘价重算市值/净值，追加 nav 历史
```

## 4. 分红除权处理

数据源：`data/companies/<code>.json` 的 `dividends` 数组（东财分红送配数据，
含 `ex_date` 除权除息日、`bonus_per_10` 10 派现金、`transfer_per_10` 10 转增）。

每日调仓第 0 步，对每个持仓依次处理满足
`bought_at < ex_date ≤ 当前交易日` 且 `ex_date > pos.div_last` 的分红记录：

| 类型 | 处理 | 会计口径 |
|---|---|---|
| 现金分红 | `cash += 持股数 × bonus_per_10 ÷ 10` | 税前入账；流水 `side=dividend`，价格列显示"现金分红入账" |
| 转增/送股 | `shares += floor(持股数 × transfer_per_10 ÷ 10)`，总成本不变、成本价摊薄 | 流水 `amount=0`，显示"转增股 N 股" |

关键语义与保障：

- **分红权判定**：建仓日必须早于除权日（`bought_at < ex_date`）。除权日之后
  买入的价格已不含权，不得重复计息；除权前卖出则由行情本身的价差不影响持仓。
- **净值不跳水**：除权日股价下调，但等值的现金分红入现金 / 股数增加摊薄成本，
  `nav = cash + Σ市值` 保持连续，当日盈亏只反映真实涨跌 + 分红收益。
- **现金自动再投资**：分红入现金后，若该标的或其他持仓/候选仍处买入档位，
  同一轮调仓的加仓/新建仓步骤会自动用掉这笔现金（复利效应）。
- **幂等与补跑**：`pos.div_last` 记录已处理的最近除权日并随 `_state.json` 持久化；
  Actions 挂几天后恢复运行，会把漏掉的多笔分红按除权日升序一次补齐。
- **转增零头**：新增股数向下取整（不足 1 股舍弃），成本同步按取整后股数摊薄。

## 5. 指标口径

| 指标 | 公式 | 说明 |
|---|---|---|
| 总资产 nav | 现金 + Σ(持股 × 现价) | 分红到账立即推高 nav（除权跌幅已在价内抵消） |
| 当日盈亏 | nav(今) − nav(上一入账日) | 含分红到账；隔周末运行为多日合计 |
| 持仓整体盈亏 | nav − 200000 | 含现金部分，现金按面值计入 |
| 每标成本价 | 加权平均成本（加仓摊薄；转增按比例摊薄） | 不做先进先出 |
| 持仓比例 | Σ市值 ÷ nav | 页面汇总；单票权重 = 市值 ÷ nav |
| 持仓天数 | 交易日 − bought_at（自然日差） | 清仓重买后重新起算 |

## 6. 数据流与文件结构

```
GitHub Actions: stock-data-update.yml（工作日 16:00 北京时间 + 手动触发）
  fetch_data.py（刷新 68 家行情与评分）
      → portfolio_engine.py（分红 + 调仓 + 记账）
      → commit & push: stock-data/data/* 与 stock-data/portfolio/data/*
```

| 文件 | 角色 | 要点 |
|---|---|---|
| `portfolio.json` | 页面渲染主数据 | `strategies.<key>` 含 nav/cash/position_pct/当日与整体盈亏/positions（含 tranches、days、pnl） |
| `trades.json` | 全部调仓流水 | 每笔 `{date, code, name, side: buy/sell/dividend, price, shares, amount, reason}`，reason 标注档位与触发依据 |
| `nav.json` | 每日净值历史 | 用于当日盈亏与幂等判定（每策略每日一条） |
| `_state.json` | 引擎内部状态 | 现金、持仓（含 tranches/div_last）、勿删；删则无法续跑 |

前端 `index.html`（Jekyll `layout: page` 嵌入博客主题）+ `assets/portfolio.js`
拉取上述 JSON 渲染：三策略页签 → 四块汇总 → 持仓（桌面表格/移动卡片）→
流水（`<details>` 折叠，倒序）。资源带 `?v=` 版本号，改动 JS/CSS 需同步提升。

## 7. 操作手册

- **本地跑一次**：`cd stock-data/scripts && python portfolio_engine.py`
  （需先有当天 `fetch_data.py` 产物；已入账日期会自动跳过）。
- **调整策略参数**：改 `STRATEGIES`（档位/上限/门槛）→ 删除
  `portfolio/data/*.json` 四个文件 → 重跑引擎即重新初始化。
  只想保留历史继续跑则不要删 `_state.json`/`nav.json`（新规则从下一交易日起生效）。
- **重新初始化**：等价于上一项的删除+重跑；流水与净值历史会清零。
- **新增跟踪标的**：走 `config.py` + 全量重抓的标准流程，引擎次日自动纳入候选。
- **验证**：改动引擎后建议跑场景测试（临时脚本 import portfolio_engine 直接调
  `cap_tranches` / `apply_dividends` 断言，历史版本各带 15+ 条边界断言）。

## 8. 已知简化与限制

1. **不计税费**：买入卖出无佣金印花税；现金分红按税前入账（实际红利税按持有期
   0~20%，模拟组合长期持有趋向免税，偏差有限）。
2. **配股未处理**：A 股配股缴款（`bonus_per_10` 体系外的 10 配 N）会被忽略，
   导致除权日净值出现一次性低估；近年配股极少，遇到再扩展。
3. **港股/美股不参与**：初始资金定义即"A 股标的"，且流派评分体系为 A 股口径。
4. **收盘价单一价格源**：买卖均按日线收盘价，不考虑盘中档位穿越顺序。
5. **买点随财报漂移**：季度报告更新后参考价重算，"现价 ≤ 买点"的判定基础会变
   （买点上调会使标的更浅地甚至不再命中档位）；这是评分体系一致性的代价与特性。
6. **卖出触发依赖 sellCons/sellFair 存在**：个别标的估值锚缺失（null）时相应
   档位跳过，仅按可计算档位减仓。
7. 数据文件被 Actions 与本模块共写，手工编辑 portfolio/data 前须先停工作流，
   否则会被下一次自动提交覆盖。
