# 行业EDB量价数据抓取与可视化搭建记录（万得 Wind 版）

---

> 这是一篇**可复用的操作手册（runbook）**。目标：下次再需要用 Wind token 抓某行业
> 的 EDB 量价数据时，照本文从「发现指标 → 批量取数 → 聚合落盘 → 前端渲染」直接开工，
> 不必重新踩坑。文中所有脚本都已在仓库里，改参数即可跑。

## 背景与目标

`stock-data/agro-price/` 原本是"农化制品价格跟踪"（抓生意社/中农立华的公开报价）。
本次把它升级为**行业 EDB 量价跟踪**：顶部加行业切换，新增 **汽车 / 电解铝 / 航运**
三个行业，数据来自**万得 Wind 宏观行业 EDB 数据库**，展示最近一年的量价走势。

与农化模块最大的不同：数据源是**需要 token（积分）的 Wind 能力**，所以整套流程的
第一约束是 **省积分**，第二约束是 **Windows PowerShell 的编码坑**（否则中文数据全乱码，
验证结果会"说谎"）。

## 最终架构

```
本地 Wind 能力  .agents/skills/wind-mcp-skill/scripts/cli.mjs
        │  （node 子进程调用，UTF-8 直取 stdout 绕开 PS 编码）
        ├─ search_economic_indicator   找指标元信息（不取数，探测 EDB 代码）
        └─ query_economic_indicator_data  按 EDB 代码批量取时间序列
        │
   fetch_edb.py（周/月聚合，省积分） → data/edb.json（静态）
        │
   GitHub Pages 静态托管 → assets/edb.js（ECharts）多维可视化
```

关键点：**Wind 只在"取数"这一步用到 token，且是本地手动/按需抓取**，不进每日定时
任务；页面渲染 100% 走本地 JSON，零 token。

## 第 0 步：一次性前置（已就绪，换机器时才需重做）

1. **安装 Wind 能力**：`wind-find-finance-skill` + `wind-mcp-skill`（装到当前项目的
   `.agents/skills/`）。调用入口统一是
   `node scripts/cli.mjs call <server_type> <tool_name> <params>`，其中 `server_type`
   取 `economic_data`（宏观/行业 EDB）。
2. **配置密钥**：`WIND_API_KEY` 写入 `.agents/skills/wind-mcp-skill/config.json`。
   ⚠️ **这是公开仓库**，务必确认 `.gitignore` 已忽略该文件（本仓库已加：
   `.agents/skills/wind-mcp-skill/config.json`）。密钥绝不入库、不写进任何文档/脚本。
3. **验证连通**：先拿一个已知 EDB 代码小样试调，确认返回信封 `isError:false` 且有
   `content[0].text`。

## 第 1 步：发现指标 —— 找到行业的 EDB 代码

EDB 指标靠**代码**取数（如 `S0000066` = CCFI 综合指数）。先探测目标行业有哪些可用指标：

1. 编辑 `.agents/skills/wind-mcp-skill/scripts/request-edb-batch.mjs`，在 `queries`
   对象里为每个待查行业加一行「自然语言问句」（例：`auto: '汽车产量 新能源汽车 产销量 相关指标'`）。
2. 运行（一次跑完所有问句，结果原样落 UTF-8 文件）：

   ```powershell
   cd .agents\skills\wind-mcp-skill
   node scripts\request-edb-batch.mjs scripts\edb_probe_raw.txt
   ```

   > 这个脚本用 `execFileSync('node', [...], {encoding:'utf8'})` **直取子进程 stdout**
   > 写文件，**关键就是绕开 PowerShell 管道**（见下方"编码坑"）。

3. 解析成清单（每行：`代码 | 名称 | 单位 | 频率 | 更新至 | 来源`）：

   ```powershell
   python .agents\skills\wind-mcp-skill\scripts\request-edb-decode.py
   ```

   产物 `.agents/skills/wind-mcp-skill/scripts/edb_probe_summary.txt`（本次去重后共 316 条）。

4. 从清单里挑选要跟踪的指标代码，**记下代码 + 展示名 + 分组标签**，填进下一步的
   `CATEGORIES`。

> `search_economic_indicator` 每个问句约 50 条封顶、**不返回时间序列、几乎不耗积分**，
> 可放心多问几句把候选池铺大，再人工挑选。

---

## 第 2 步：批量取数 + 聚合落盘 —— `fetch_edb.py`

脚本位置：`stock-data/agro-price/scripts/fetch_edb.py`。核心设计：

- **指标清单在 `CATEGORIES` 里维护**（三类，每类是 `(EDB代码, 展示名, 分组标签)` 元组列表）。
  换行业/加指标，只改这里。
- **每分类一次调用、逗号批量传代码**（共享同一日期区间），最大化减少调用数：

  ```python
  params = {"question": ",".join(codes), "beginDate": begin, "endDate": end}
  ```

- **省积分的周/月聚合**（`collapse_weekly`）：按「跨度天数 / 点数 < 5」判定是否为日频，
  是则按 ISO 周折叠成"每周最后交易日"的值；周频、月频原生序列**原样保留**（月频无法用
  更少数据补出）。默认只取**最近一年**（`begin = 今天 - 365`，可 `--begin/--end` 覆盖）。
- **瞬时 `backend_error` 自动重试**：批量偶发某类返回空（`[warn] ... 无数据返回，跳过`），
  重跑该类即可。⚠️ 全量运行会覆盖整份 `edb.json`；只想更新某一类时用 `--only <id>`，
  脚本会把该类**合并写回**、保留其它分类（省积分、不重抓）。

运行：

```powershell
cd stock-data\agro-price\scripts
python fetch_edb.py --begin 2025-01-01  # 全部分类，从 2025-01 起（留足一年历史算同比）→ ../data/edb.json
python fetch_edb.py --only alu          # 只抓 alu 一类并合并写回（保留其它分类，省积分）
```

### `cli.mjs` 调用契约（fetch_edb.py 内部用的方式）

```powershell
cd .agents\skills\wind-mcp-skill
node scripts\cli.mjs call economic_data query_economic_indicator_data @scripts\request-edb-<ts>.json
```

- 含中文的参数**用 `@文件` 方式传入**（Python 侧 `subprocess.run(..., encoding='utf-8')`
  把参数写成 UTF-8 临时 json，用完即删），**不要**把中文 JSON 直接拼进命令行——会被 PS 篡改。
- **返回信封**（所有工具一致）：

  ```jsonc
  { "content": [ { "type": "text", "text": "<这里才是业务 JSON 的字符串>" } ],
    "isError": false, "cli_meta": { ... } }
  ```

  → 先 `json.loads(env["content"][0]["text"])` 拿到业务 payload。

- **两个工具的 payload 形状不同，别记混**：
  - `search_economic_indicator` → `payload["metrics"]`，每项是**扁平**元信息
    `{code, name, unit, freq, updateDate, source}`。
  - `query_economic_indicator_data` → `payload["metrics"]`，每项是
    `{meta:{code,name,unit,freq,source}, date:[...], value:[...]}`（时间序列在 `date`/`value` 平行数组）。

## 第 3 步：产物 `data/edb.json` 结构

```jsonc
{
  "updated_at": "2026-08-30T13:26:09+08:00",
  "range": { "begin": "2025-01-01", "end": "2026-08-30" },
  "categories": [
    { "id": "auto", "name": "汽车",
      "indicators": [
        { "code": "S0105523", "name": "中国:产量:汽车",
          "label": "汽车产量", "unit": "辆", "freq": "月",
          "source": "中国汽车工业协会", "group": "产量",
          "points": [ ["2025-08-31", 2449865], ["2025-09-30", 2815413], ... ] }
      ] }
  ]
}
```

本次产物：4 分类 / 25 序列（汽车 7 · 电解铝 4 · 航运 9 · 轮胎橡胶 5），区间统一从 2025-01 起以支持月级同比。

## 第 4 步：前端渲染（`assets/edb.js`）

约定与"农化制品/汽车/电解铝/航运/轮胎橡胶"切换栏配合：`index.html` 顶部 `#edb-switch` 5 个按钮，
`edb.js` 负责协调原有 `agro.js` 视图与新 EDB 视图显隐，EDB 数据首次切到某行业时才
`fetch('./data/edb.json')` 懒加载并缓存。

每个行业渲染三层（维度图配置集中在 `edb.js` 的 `DIM_SPECS`）：

1. **KPI 指标卡**：最新值 + 单位 + **环比**（末点 vs 前一点）+ **同比**（末点 vs 去年同月，
   `yoyChg`）+ 区间位置条。⚠️ 同比只有在数据回溯到 ≥ 13 个月前才有值，故 `--begin` 至少
   取到"上一年同月"（本次统一到 2025-01-01）；但仍**不要**放"区间涨跌"徽章——那是首末整体
   变化、与同比重复且口径含糊。⚠️ `yoyChg` 求"去年同月"的 key 必须用本地 `getFullYear/Month/Date`
   格式化（同 `toISOString` 时区坑，见踩坑 8/9）。
2. **相对走势总览**：**所有指标归一为"起点 = 100"** 再叠一张折线图。
   ⚠️ **同分类内单位/量级差异极大**（万辆 vs 辆 vs % vs 元/吨 vs 指数点），**绝不能用同一
   原始数值轴叠加**，只能比相对涨跌。
3. **多维度分类图**：只有**单位相近**的指标才放同一张图，例如：
   - 汽车：汽车/新能源产量柱 + 渗透率线（**双 y 轴**，产量"辆"×1e-4 折算"万辆"）、
     产销对比（汽车产/销 + 新能源产/销）、乘用车 vs 比亚迪（均中汽协"辆"）。
   - 电解铝：铝价 vs 氧化铝成本（同为元/吨直接叠）、**吨铝价差面积图**（两序列按日期对齐后相减）、
     LME 铝（美元计价，独立画）。
   - 航运：CCFI & SCFI 综合、CCFI 分航线、散货油运 BDI/BDTI/沿海。
   - 轮胎橡胶：轮胎产量（柱，万条）& 出口额（线，万美元，**双 y 轴**）、橡胶原料价格（天然/丁苯橡胶同为元/吨直接叠）、半钢胎开工率（%）。

**必须记住的渲染坑**：ECharts 在 `display:none` 的容器里 `init` 尺寸为 0。做法是——
先切到目标视图（显示容器）再 `renderCategory` + 渲染后 `setTimeout(()=>chart.resize(),0)`；
从 EDB 切回农化时调用 `window.__agroRefresh()`（`agro.js` 暴露的钩子）恢复原图尺寸。

## 省积分 / token 控制要点

- **发现阶段用 `search`**（不取数、几乎不耗），把候选池铺大再挑；真正耗积分的只有
  `query` 取数。
- **一次调用逗号批量传同类多代码**，共享日期区间，别一个一个码各调一次。
- **周/月聚合**：日频折周频，既减小 JSON，也符合"趋势够用即可"。
- **只取最近一年**，按需**手动重抓**，不进定时任务。
- 若要**扩很多指标 / 拉多年 / 日频原始曲线**（预计消耗明显变大），**先估算再跟本人确认**。

## 踩坑记录（下次别再踩）

1. **PowerShell 管道 GBK 误解码 node 的 UTF-8 中文输出** → 全乱码，验证结果"说谎"。
   规避：**永远用子进程直取 stdout**（Node `execFileSync({encoding:'utf8'})` 或 Python
   `subprocess.run(encoding='utf-8')`）落文件，再用编辑器/Python 解析，不要 `>` 重定向或 `|`。
2. **含中文的 `.ps1` 字面量报 ParserError**：PS5.1 按 ANSI 读无 BOM 的 UTF-8。规避：脚本
   改用 `.mjs` / `.py`，彻底绕开 PS 中文解析。
3. **某类返回空（瞬时 `backend_error`）**：重跑该类即可；`--only <id>` 现在是**合并写回**
   （保留其它分类），不会丢数据。
4. **ripgrep（Grep 工具）对单行大 JSON 返回 0 匹配**：连 ASCII 代码都搜不到，是工具对
   长单行的限制，**不是数据问题**。改用 Python `json.load` 或 `t.count('中文')` 校验。
5. **"同比/区间涨跌"没意义**：区间恰好一年时没有去年同期点、"区间"又只是整体首末变化，
   展示上直接去掉，只留**环比**。
6. **单位混叠**：EDB 单位串里会出现 `1998年1月1日=1000` 这类指数基准，展示时归一为"点"。
7. **统计局"当月值"缺 1–2 月**：`中国:产量:汽车:当月值` 等国家统计局月度序列，因官方惯例
   **每年 1–2 月合并发布**，序列里会**整段缺 1、2 月**，画出来早期出现缺口。需要连续月度
   口径时改用**中汽协**等协会序列（如 `S0105523 汽车产量`、`S6139215 新能源汽车产量`，单位"辆"）。
8. **ECharts time 轴 tooltip 时区倒退一天**：`new Date(axisValue).toISOString().slice(0,10)`
   在 UTC+8 下会把"本地零点"的时间戳转成**前一天**，据此回查原始值会**错取上一期**。规避：
   用**本地 `getFullYear/Month/Date`** 格式化，或直接用数据点自带的日期串匹配。
9. **`yoyChg` 同样有 `toISOString` 时区坑**：算"去年同月"的 key 也要用本地格式化，否则
   月末点会错配到上一期；同比要有值，`--begin` 必须覆盖到去年同月。
10. **个别 EDB 码批量取数返回空（`[warn] ... 无数据返回`）**：多为瞬时 `backend_error` 或
    该码在所选区间确无数据（如 `S9987482 全钢胎开工率`）。缺一个不影响模块，用同类替代
    （半钢胎开工率）即可；非要补就 `--only <id>` 重跑该类（合并写回、不重抓其它）。

## 下次开工 Checklist

**A. 新增一个行业（如"水泥""白酒"）**

1. 在 `request-edb-batch.mjs` 的 `queries` 加该行业问句 → 跑 batch → 跑 decode →
   在 `edb_probe_summary.txt` 挑好指标代码。
2. 在 `fetch_edb.py` 的 `CATEGORIES` 加一类 `{id, name, indicators:[(代码,展示名,分组)...]}`。
3. `python fetch_edb.py` → 校验 `data/edb.json`（用 Python `json.load`，别用 Grep）。
4. 在 `edb.js` 的 `DIM_SPECS` 加该 id 的维度图配置（按单位相近分组，异单位靠归一化总览）。
5. 在 `index.html` 的 `#edb-switch` 加一个 `<button class="edb-seg" data-view="新id">行业名</button>`。
6. 本地 `python -m http.server` + 浏览器验证：切到新行业看 KPI/总览/维度图是否正常、控制台零报错。
