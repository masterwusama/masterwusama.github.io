# A股财务分析数据服务搭建记录

---

## 背景

最近在做一个上市公司财务分析 App，最核心的问题是：**财务数据从哪来**？

调研了一圈：

- 商业 API 要钱，个人学习成本太高
- 自己租服务器 + 定时抓取，要运维
- 用 GitHub Pages 当"服务器"？Pages 只托管静态文件，不能跑后端代码

最终方案：**GitHub Actions（云端定时跑 Python）+ GitHub Pages（静态 JSON 托管）**，
零成本、零运维，数据自动更新。

## 整体架构

```
GitHub Actions（定时任务，每天 3 次：北京 9:00 / 17:00 / 次日 1:00）
   └─ Python + AKShare 抓取公开接口 → 标准化 JSON → 自动 commit
                        ↓
        GitHub Pages 发布
                        ↓
        https://masterwusama.github.io/stock-data/data/{index|companies/*}.json
                        ↑
        Android App / 博客页面 直接 GET
```

## 数据源与内容

全部使用**免费公开接口**，无需 token：

| 数据 | 来源 | 说明 |
|------|------|------|
| 财务指标（ROE/毛利率/净利率等） | 同花顺摘要 | 最近 8 个报告期 |
| 三大报表（利润/资产负债/现金流） | 新浪财经 | 最近 8 期，全字段 |
| 估值快照（价格/PE/PB/市值/换手率） | 腾讯行情 | 每次更新抓最新值 |
| 分红历史（送转派息+关键日期） | 巨潮资讯 | 全量（10~30 条/家） |
| 定期报告 PDF 直链 | 巨潮资讯 | 最近 3 年，年报/半年报/一季报/三季报 |

**数值统一标准化**是数据层最重要的设计——原始值 `"272.43亿"`、`"1.47%"`
在服务端统一解析为 `27243000000.0`（元）、`0.0147`（小数），客户端拿到就是
干净的数值，不需要再处理单位。

当前跟踪 4 只股票：分众传媒、广信股份、人福医药、东宏股份。

## 踩坑记录

### 1. 东财接口说挂就挂

第一个版本用东方财富的报表接口，结果 `stock_profit_sheet_by_yearly_em`
直接报 `TypeError: 'NoneType' object is not subscriptable` —— 页面结构改版，
AKShare 解析挂掉。**换用新浪源后稳定**。教训：抓取类接口随时可能因源站
改版失效，脚本里每个数据源都要 try/except 降级，不能一家挂全挂。

### 2. 本地代理让"测试通过"失真

本机有代理，东财接口全部连不上，但新浪/腾讯/巨潮正常。导致本地测试时
`info`（行业等）字段为空。**GitHub Actions 环境没有代理问题**，上线后自动
恢复。教训：本地环境差异会影响接口可用性，最终以 Actions 环境为准。

### 3. 一个隐蔽的编码坑

页面用 JS 拉取 JSON 渲染，本地预览时发现：列表正常，但报表期数下拉全是
`-`、股息率算不出来。排查半天，根因是**页面没有声明 charset，外部 JS 里的
中文字段名（`'报告日'`）被按错误编码解析**，而数据里的中文（JSON 按 UTF-8
解析）是正常的——所以"数据正常、逻辑失效"。

修复：页面加 `<meta charset="utf-8">` + `<script charset="utf-8">` 双重声明。
线上 GitHub Pages 自带 charset 响应头没有此问题，但这是本地调试的大坑。

### 4. 控制台编码让验证结果"说谎"

Chrome headless 输出 UTF-8 DOM，经过 PowerShell 管道后按 GBK 解码再编码，
中文全变乱码，差点误判页面渲染失败。最后改为**子进程直接捕获字节流**
才拿到真实结果。教训：验证管道的编码问题会掩盖真实 bug。

## 博客集成：股票分析模块

数据服务搭好后，顺手在博客里集成了展示入口（导航栏新增"股票分析"）：

- **列表页**：公司卡片，点击进入详情
- **详情页**：
  - 估值快照卡片（PE/PB/市值/换手率/股息率）
  - 关键指标趋势图（ECharts：营收/净利润柱状 + 毛利率/ROE 折线）
  - 三大报表 Tab 切换 + 报告期选择
  - 分红历史列表
  - 定期报告 PDF 直链（点击直接打开官方原文）

## 小结

- 静态托管 + 定时任务，**零成本**跑通了一个"伪后端"数据服务
- 数据量小时这个方案非常舒服；将来要支持任意股票实时查询、更大数据量时，
  再平滑迁移到轻量服务器（代码基本不用改，换 base URL 即可）
- 下一阶段：Android App 端接入这些数据，做估值对比、杜邦分析等功能
