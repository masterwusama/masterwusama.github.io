# 跑团桌模块搭建记录

---

## 背景

和桌游党朋友线下开 D&D 团，最大的痛点是**桌面堆不下书**：骰子、角色卡、法术列表、
怪物图鉴、遭遇难度表……每个人手上三个 PDF，翻页比跑团还累。

于是想在博客里加一个"跑团桌"：一个页面把掷骰、建卡、查数据、算遭遇全装下。
约束和冰箱做菜一样老两条：

- GitHub Pages 只有静态文件，**没有后端**
- 工具要**开箱即用**，点开就是，不折腾

## 第一阶段：一天搭出九件套（08-09）

跑团桌从第一行代码到九件套只花了一天，全靠**数据驱动**的思路撑住：

1. **掷骰器**——d4~d100、表达式（`2d6+3`、`4d6k3`）、优势/劣势/暴击、历史记录
2. **角色卡**——多槽位、导入导出 `.dnd.json`
3. **随机表**——人名/性格/事件，后来增强成动态遭遇、战利品稀有度加权、NPC 附加细节
4. **魔法书**——全法术中文译名 + 环形搜索（戏法 24、1 环 49、2 环 54…）
5. **怪物图鉴**——**334 个怪物**，中文译名 + 搜索
6. **装备库**——SRD 装备 + 2024 专长速查
7. **职业升级**——升级表（后来加了横向滚动，窄屏不再挤压）
8. **遭遇计算**——队伍配置 → XP 阈值（简单/中等/困难/致命）→ CR 选择器
9. **魔法物品**——362 件库 + 稀有度/类型筛选 + 随机生成器

这个阶段最大的工程是**本地化**：SRD 原始数据是英文的，魔法书和怪物图鉴的中文译名
必须和玩家手中的实体书对得上。做法是数据文件里维护译名字段、前端做中文搜索索引——
纯前端也能做出"输入中文查怪物"的体验。

## 第二阶段：文字冒险引擎（08-09 ~ 08-16）

工具集齐了，但"跑团桌"只有工具没有故事，总觉得缺了什么。
于是开始做**文字冒险模块**：《极乐迪斯科》风格的原创剧情。

这一周从 144 节点初版，一路进化到 6000 多行剧本的完整引擎，按里程碑回顾：

### 失忆开局（08-10）

开局主角记不清自己是谁：欢迎页不泄露姓名/职业，玩家名默认 `？？？`，
靠翻笔记本、对着镜子、被同事点名三处剧情逐步"认领"身份。
引擎为此支持了 `name/job/place` 三种身份字段的动态解锁——状态栏从 `？？？ · ？？？`
变成 `哈利·杜博阿 · 警探 · 瑞瓦肖` 的过程，就是失忆到清醒的过程。

### 官方剧情重构（08-11）

初版 144 节点是"风格类似"的原创剧情，玩家玩着玩着觉得不对味。
于是干脆按官方原版剧情重写：**Day1~Day4 + 审判日 + 结局树**（真相大白 / 大屠杀幸存 /
死亡 / 辞职四条线），数据层对齐官方译名（24 技能 / 19 NPC / 45 物品 / 想法 / 怪物）。
剧本规模从此爆炸：四个 story 文件共 **6124 行**。

### 属性驱动检定（08-11）

"检定永远成功"是文字冒险最出戏的事。重构后：
24 个技能分属 4 个属性（智力/精神/体格/运动），技能值 = 属性 + 装备加成 + 额外点 + 醉酒惩罚；
开局 12 点属性分配；5 个装备槽（颈/衣/裤/脚/手）提供技能加成；消耗品作用于 HP/士气/醉酒。
检定弹窗实时展示数值分解：`d20 + 属性 + 装备 + 额外点 + 醉酒`——玩家能看懂自己为什么过/不过。

### 失败有后果（08-12）

新问题：**失败没代价**。足迹鉴定失败了可以无限重试，偷卡被发现了还能再偷，
权威对峙输了还能接着问——叙事张力全无。于是引入 `fail_flag` 机制：
关键检定失败后设置永久标志，对应选项/任务**永久关闭**（足迹分析失败 → 该选项永远消失；
对峙失败 → 直接卷铺盖走人）。"失败要有后果"是 CRPG 的第一性原理。

### 被动检定（08-15）

主动检定解决后，发现**技能叙述段**也在剧透：剧本里 331 处 `[技能名]` 开头的技能旁白
无论属性高低全部显示——属性 1 的乡巴佬和属性 6 的博学家看到的信息一样多。
于是加被动检定：`PASSIVE_DC = 12`，技能段检定通过才揭示内容，失败留下灰色记录
`✗ 技能名 被动检定失败 · d20 X + Y = Z / DC 12`。同时开局隐藏职业和城市名，
靠剧情推进解锁——不知道自己在哪座城，才是真失忆。

### 选项锁定与检定沿用（08-15）

被动检定又带出一个体验问题：**刷新页面，检定结果重掷**——刚才检定通过的选项，
刷新后变成失败，再刷新又通过，存档形同虚设。
修复后：被动检定首次掷骰结果立即固化并落盘；主动检定成功的选项**灰显禁用**（保留可见，
避免"选项全消失无路可走"的卡死）；入口全部检定时入口选项也锁定。

### 补全与收尾（08-16）

全量审计发现"后续场景没检定"的真相：剧本重构时大量技能叙述段漏写了方括号
（`天人感应— 瑞瓦肖是世界的中心` 而非 `[天人感应] ...`），引擎只认方括号格式。
修复 23 处、补 21 个场景主节点 30 段检定，并在校验器里加了"漏方括号检测"防复发。

## 踩坑记录

### 1. 渲染期数据不落盘 → 刷新重掷

被动检定结果在**渲染阶段**才首次掷骰，而自动存档在节点跳转时写入——当前节点的
新掷结果没落盘，一刷新就重掷，d20 数值与成败随机变化。

> **教训**：任何"渲染时才产生、需要刷新后沿用"的数据（检定结果、骰值、动态计算），
> 必须在产生点立即持久化，不能依赖后续的统一存档时机。

### 2. 双重 JSON.parse → 刷新白屏

修上面问题时踩了连环坑：恢复自动存档时对已经 `JSON.parse` 过的对象再 `parse` 一次，
抛 `"[object Object] is not valid JSON"`，整个页面白屏。
修复是恢复流程改为"parse 一次、其余地方只引用"。

> **教训**：存档恢复时确认数据是否已被解析，避免双重解析——这种错误只在刷新时出现，
> 开发期根本不会碰到。

### 3. 技能段漏方括号 → 检定静默失效

玩家反馈"后续场景这些检定都没做"，排查发现引擎只识别 `^[技能名]` 开头的段落，
剧本里 23 处漏了方括号的技能叙述全被当普通旁白。更坑的是**结果节点不能乱补**：
主动检定成功/失败分支里的技能段补上方括号会触发二次独立检定，失败时关键叙述被隐藏。

> **教训**：格式约定必须配校验器——人工写 6000 行剧本不可能不出格式错，
> 让校验器兜底，并给"有意不加方括号"的节点留豁免名单。

### 4. 引擎扩展了，校验白名单忘了 → 静默丢弃

`effect` 字段新增 `name/job/place` 支持后，`verify_*.js` 的合法字段白名单没同步——
新字段在校验阶段被**静默丢弃**（无报错、无日志，效果不生效），排查了一晚上。

> **教训**：数据驱动的引擎，**每次扩展字段必须三步走**：引擎实现 + 校验白名单 + 数据使用，
> 少一步都是静默故障。

### 5. 技能数值跨层口径不一 → 条件失效

`cond: 'skill:xxx>=N'` 条件判定曾用"额外点"而非技能总值，导致属性加点、装备加成
全部不生效，条件永远只能靠想法点数满足，检定与条件语义失真。

> **教训**：同一技能数值在条件、检定、被动检定、UI 展示处**必须共用一个取值函数**，
> 新增任何加成来源后都要复查所有口径。

### 6. CSS 变量作用域 → 弹窗文字黑色不可见

检定弹窗挂在 `body` 下，`#dnd-app` 上的 CSS 变量（文字色、金色主题）不生效，
弹窗文字在深色背景上显示成黑色。修复：弹窗组件补齐自己的变量声明。

### 7. 负面修正被 clamp 吞掉

`applySkillEffects` 把负值钳制为 0，`-1 从容自若` 这种负面效果被静默丢弃。
移除钳制、允许负值后，醉酒和负面想法才真正生效。

## 急流勇退：移除文字冒险（08-16）

一周迭代后必须承认一个架构级问题：**剧本撰写太自由了**。

节点结构只有 `text/choices/goto` 三个自由字段，6000 行剧本全靠作者自觉维持线路一致。
结果就是剧情线路顺序出现巨大差错——这不是再补几个校验规则能救的，
是**剧本语言本身缺少约束**：没有类型化节点、没有前置条件体系、没有状态声明。

最终决策：**整体移除文字冒险模块**（10 个文件、7744 行，含引擎、数据、四天剧本），
而不是带病修补。git 历史完整保留，教训沉淀为设计准则：

- 节点必须**类型化**（dialog/check/battle/effect/cutscene），消灭自由文本
- 剧情状态**全量显式 flag**，初始白名单声明，杜绝隐式状态
- 剧情顺序由**地图可达性 + flag 前置条件**双重控制——拿不到钥匙就进不了地窖
- 校验器是**开发门禁**：悬空引用/孤儿 flag/不可达节点/死锁检测，不通过禁止合入

基于这些准则，新项目已立项：**RMMV 式恐怖生存 RPG**（参考《恐惧与饥饿》），
纯前端 Canvas 零依赖，导航新入口"在线游戏"（`rpg/`），设计文档已定稿，
正在按里程碑开发（M0 技术验证 → M1 玩法闭环 → M2 战斗 → M3 内容）。

## 小结

- **纯前端能做的事比想象中大**：334 个怪物的图鉴、6000 行剧本的引擎，GitHub Pages
  都扛得住，关键是数据驱动 + 分层清晰
- **工具的价值靠数据，内容的价值靠约束**：工具集九件套靠数据文件撑起来没出大问题；
  文字冒险翻车在"内容层完全没有约束"，写的人自由、查的人绝望
- **校验器不是可选优化，是长内容项目的生命线**：6000 行剧本，人工核对格式是不可能的，
  让脚本兜底、把规则固化成门禁，才有胆子继续写内容
- **移除不是失败**：带病修补的维护成本远高于重写，git 历史里的一切都是下一版的素材

下一步：`rpg/` 项目的 M0 里程碑，敬请期待。
